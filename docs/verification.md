# Verification record

Executed locally on Apple Silicon with macOS 26 and Apple Swift 6.2.1. The package targets macOS 14+; this record does not establish runtime coverage on every supported OS or architecture.

## Build and automated checks

- `make build`: release compilation, generated original icon, app-bundle packaging, and ad-hoc signing succeeded.
- Both default signing and `CODE_SIGN_IDENTITY` certificate signing were exercised through `make build`, then checked with `codesign --verify --strict`. The selected local certificate produced an identifier-and-Apple-certificate designated requirement instead of the default binary-hash-only requirement.
- `swift test`: **15 Swift Testing tests in two suites passed**. Coverage includes physical-pixel orientation, crop/resize/composition, color sampling, opaque redaction with translucent chosen colors, masked magnifier sampling, redaction precedence over pixelation, editable undo/redo after crop, exact overlap rows, stationary duplicates, static header/footer handling, rejected ambiguous/unmatched content, and narrow moving content.
- Local Markdown links and all three PNG screenshot assets were checked for valid targets and image headers.

## Native application checks

The built application was launched through LaunchServices. Native Accessibility actions opened the bundled example and selected tools; real pointer events created an arrow, rectangle, and opaque mask, then moved the mask over the example address. Backdrop selection and Select were exercised. The resulting editor visibly reported three annotations and fitted its decorated image.

The actual **Read text & QR** action opened its review sheet. Apple Vision recognized the example text; the masked address was absent from the displayed result. The public welcome/editor/OCR screenshots are captures of that running app, not UI mockups. Their example artwork is generated by screenboop and explicitly labeled as an example.

A separate native executable using the production source exercised image import/history round-trips, PNG/JPEG export, clipboard pixel equality, upright multiline text and QR recognition, mounted-canvas coordinate conversion, a visible floating pin and its close button, and delayed-capture cancellation/ownership cleanup. Coordinate assertions allow floating-point roundoff, not a different pixel location.

## Real screen acquisition

A controlled scrollable native test window covered the capture display. The production `CaptureService` was exercised from a throwaway native host with explicit Screen Recording and Accessibility grants:

| Workflow | Observed output |
| --- | --- |
| Main-display capture | 3456 × 2234 pixels |
| Native area picker | 1282 × 994 pixels |
| Native window picker | 3456 × 2234 pixels |
| Escape in native area picker | No image; capture ownership released |
| Rectangular selection, injected scroll events, overlap composition | 1280 × 10758 pixels at the 20-frame bound |

The test window was closed afterwards. No personal desktop capture was added to the repository. Precise seam-pixel and stationary-bottom assertions use deterministic synthetic frame sequences; the live run does not establish arbitrary app/browser compatibility or real-world bottom detection.

The picker smoke exposed that this macOS version exits normally with status 0 and no file when Escape dismisses the picker. The capture-result boundary now recognizes status 0 or 1 with no output/diagnostic as dismissal, while ordinary failed acquisition remains an error. The live Escape scenario passed after that change.

### Installed app permission recovery

A local ad-hoc build exposed a stale macOS recording grant: the privacy switch was enabled, but TCC logs reported a code-requirement mismatch against an older binary hash. The build was signed with an existing local development certificate, only `dev.screenboop.mac`'s ScreenCapture grant was reset through `tccutil`, and the app received a fresh grant and was restarted. The stored requirement then bound the app identifier and certificate rather than the obsolete hash. Permission checks remained intact.

The certificate-signed `/Applications/screenboop.app` was then exercised through its own **Area** action and native picker against a generated two-color window. It acquired and displayed a **1242 × 562** PNG with the expected red/green content, without the permission error. This establishes a successful capture from the installed app, not just the separate native smoke host. The generated test window was closed afterwards.

## Limits

- The launched screenboop app has its **own** macOS privacy identity. Its first denied capture was exercised: it returned to the unchanged example and showed an actionable permission message. Successful acquisition from the permitted native host does not grant permission to the app bundle; users must enable screenboop separately.
- Automated tests do not grant permissions, drive pickers, or prove scroll-event delivery. GitHub CI runs the permission-free tests and build, not unattended desktop capture.
- Secondary-display scrolling, arbitrary sticky/animated layouts, all hardware configurations, Developer ID signing, notarization, and App Store distribution are not verified here.
- No comparative performance, OCR-accuracy, or equivalence benchmark against Shottr was run.
